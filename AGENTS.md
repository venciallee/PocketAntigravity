# PocketAntigravity Engineering & ESDD Guidelines (v2.0 UE Aligned)

1. **Architecture (KMP Monorepo)**:
   - `shared/` is the Kotlin Multiplatform shared core (`:shared:core-model`, `:shared:core-protocol`, `:shared:core-markdown`, `:shared:core-domain`, `:shared:umbrella`), providing Ktor (OkHttp/Darwin) Connect-RPC & Cloud Relay networking, 5-byte framing, Binary Protobuf decoding, `StateFlow` domain stores, and SKIE-exported `AntigravityShared.xcframework`.
   - `apps/ios/Packages/AntigravityData` is a pure Swift 6 package containing the `@Observable` `AntigravitySessionStore`, pure-Swift `AntigravityKmpEnginePort`, local display projection (`LocalProjectionStore`), Durable Outbox, Keychain store, and extension-safe Connect-RPC client. It never imports `UIKit` or `AntigravityShared` (keeping WidgetKit & Share extensions safely under 30MB).
   - `apps/ios/App/` owns all 13 native UE controllers & sheets plus the main-app SKIE bridge (`apps/ios/App/Bridge/`): `AntigravityShellController`, `AgentsHomeViewController` (`UE01`), `DisplayOptionsSheetView` (`UE02`), `ConversationContextPreviewMenu` (`UE03`), `ProjectDetailViewController` (`UE04`), `CreateProjectSheetView` (`UE05`), `AutomationsViewController` (`UE06`), `CascadeChatViewController` + `ChatComposerView` (`UE07`), `AddContextSheetView` (`UE08`), `ModelAndModeSheetView` (`UE09`), `StructuredQuestionCardView` (`UE10`), `ImplementationPlanReviewViewController` (`UE11`), and `TurnDiffReviewViewController` (`UE12`).
   - `apps/ios/SharedUI/` & `apps/ios/Extensions/` own iOS-only `AntigravityTheme` (`#090A0D` Matte Obsidian, `#8EB4FF` Periwinkle CTA, `#EBB365` Face ID Amber Approval), `AntigravityGlass`, `AntigravityActivityAttributes`, `AntigravityLiveActivityWidget` (`UE13`), and `AntigravityShare`.
   - `apps/android/` is reserved for the upcoming native Kotlin / Jetpack Compose Android client consuming `shared/`.
   - `tests/ios-ui/` owns the native XCUITest suite (`AntigravityUITests`).

2. **ESDD (Executable Spec Driven Development) Verification**:
   - All 13 UE states (`UE01_AGENTS_HOME` .. `UE13_LIVE_ACTIVITY_SPEC`), 13 navigation transitions (`E01` .. `E13`), and 13 claims (`CLAIM-01` .. `CLAIM-13`) are declared in `specs/esdd-ir.json`, alongside 16 interactive E2E test cases (`TC-01` .. `TC-16`) in `specs/02-esdd-e2e-test-plan.md`.
   - Offline deterministic fixtures are registered in `apps/ios/App/Application/DebugSceneFactory.swift` and routable via `antigravity://verify/<case>` with `--ui-verify`.
   - **Unified Verification CLI (`scripts/verify.py`)**: Run `./scripts/verify.py` (fast ~7s gates: `spec`, `rpc`, `v233`, `compat`), `./scripts/verify.py --auto` (impact-scoped ESDD + fast gates), or `./scripts/verify.py --full` (adds full 4-gate `esdd`, `kmp`, and `swift` when available; `--json` for structured agent output; auto-restores `verification/output/` so `git status` stays clean).
   - **Impact-Scoped E2E vs Mandatory Release Full E2E (`verification/e2e_impact_planner.py`)**:
     - **Normal Development / PRs (Impact-Scoped)**: Evaluate the change blast radius via `python3 verification/e2e_impact_planner.py --include-working-tree` (or `./scripts/verify.py --auto` / `python3 verification/esdd-verify.py --auto`). Only affected gates, Swift tests, modular XCUITest methods (`AntigravityInteractiveUITests` 5 domain methods), Simulator UE screens (`UE01`..`UE13`), and ESDD interactive cases (`TC-01`..`TC-16`) are executed — unaffected cases are skipped, and pure docs/script/Android/KMP-only PRs skip booting the `macos-15` Xcode Simulator runner entirely. Global core files (`project.yml`, `apps/ios/App/Application/AntigravityApp.swift`, `apps/ios/App/Navigation/AntigravityShellController.swift`, `apps/ios/SharedUI/DesignSystem/*`, `apps/ios/Packages/AntigravityData/Sources/AntigravityData/Store/AntigravitySessionStore.swift`, CI/runner scripts) and unmapped Swift files conservatively escalate to `full`.
     - **Release Verification (Mandatory 100% Full E2E)**: Any release trigger — GitHub `release` event, release tag (`v*`, `release-*`), `release/*` branch, `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` version bump in `project.yml`/`Info.plist`, PR label (`release` / `full-e2e`), commit/PR marker (`[release]` / `[full-e2e]` / `release:`), or explicit `--release` / `workflow_dispatch(verification_mode=release)` — **MUST** execute 100% FULL E2E across all 4 ESDD stages (`16/16` TCs + `13/13` `@3x` screens + `CMP_UE01..CMP_UE13`), all 5 macOS Gates (all `AntigravityData` XCTests, Live Connect-RPC + v2.33 + 3-version Compat Matrix, all 5 XCUITests, Live App Connect-RPC handshake, all 13 native iOS Simulator screenshots), and full KMP JVM + iOS XCFramework E2E.
   - Run `./scripts/verify.py --auto` (or `python3 verification/esdd-verify.py --auto`) for fast impact-scoped local ESDD checks, or `./scripts/verify.py --full` / `python3 verification/esdd-verify.py --release` to execute the full 4-gate E2E suite:
     1. Mechanical Spec-DAG & Swift 6 Source Contract completeness validation.
     2. Connect-RPC 5-byte envelope, >600-step Binary Protobuf, Face ID Interaction, Project, and Automation E2E tests against `verification/mock_language_server.py`.
     3. 16 Interactive E2E user-journey flows (`TC-01` .. `TC-16`) in headless `393×852pt @3x` viewport.
     4. Pixel-accurate `@3x` screenshot rendering, HIG geometry audit (`0px` horizontal overflow), and 1:1 Side-by-Side Reference UE vs Implemented comparison sheets (`verification/output/comparisons/CMP_UE01..CMP_UE13.png`).

3. **End-to-End Autonomous Delivery & macOS Xcode / iOS Simulator CI Verification (Mandatory for Code/Config Changes)**:
   - This repository is a **KMP + Swift 6 / iOS 18** Monorepo (`project.yml`, `shared/`, `apps/ios/`, `apps/android/`, `tests/ios-ui/`). Remote Linux agent VMs do **not** have `swiftc`, `xcodebuild`, or the iOS Simulator installed.
   - Pure documentation changes (`README.md`, `AGENTS.md`, `docs/**`, `LICENSE`, `NOTICE`) are automatically classified as `docs-meta` by `verification/e2e_impact_planner.py` (`needs_macos=false`), skipping the `macos-15` Xcode/Simulator runner completely.
   - **Never stop at local-only edits or Linux-only static/Python checks for code/config/build changes.** Unless the user explicitly requests a draft/no-merge workflow (e.g. "先别合" / "draft PR only"), every development task **MUST** automatically execute the complete closed-loop delivery pipeline without waiting for the user to ask:
     1. **Sync & Branch**: Fetch latest `origin/main` and branch cleanly off `origin/main` (e.g. `fix/<topic>`, `feat/<topic>`, or `chore/<topic>`). Never push directly to `main`.
     2. **Local Fast Verification**: Run `./scripts/verify.py` (or `./scripts/verify.py --auto` / `--full --json`; use `python3 verification/esdd-verify.py --release` before cutting a release). `scripts/verify.py` runs `spec` (incl. `e2e_impact_planner.py --self-test`), `rpc`, `v233`, and `compat` guardrails + 3-version matrix, automatically skips unavailable macOS-only toolchains on Linux, and restores unmodified `verification/output/` artifacts unless `--keep-artifacts` is passed.
     3. **Auto Commit & Push**: Commit all verified changes with a clear conventional commit message and push the branch to `origin` (`git push -u origin <branch>`).
     4. **Auto Open PR (MR)**: Open a Pull Request targeting `main` (`gh pr create -R venciallee/PocketAntigravity --base main --head <branch> --title "..." --body "..."`), which triggers `.github/workflows/macos-xcode-verify.yml` (and `.github/workflows/kmp-verify.yml` when `shared/**` changes).
     5. **Watch CI Gates to Completion**: Monitor the workflow run(s) until completion — prefer low-frequency checks (`gh run watch -i 45`) to avoid exhausting GitHub REST API rate limits — and verify **all scheduled gates** pass green (impact-scoped on normal PRs; **100% full 5-gate macOS + ESDD + KMP** on releases or global-core changes):
        - `[Gate 0]` Impact Planner + Script syntax, Doc-Sync watcher self-test, impact-scoped static compatibility guardrails (`verify_compat_guardrails.py`, when `Protocol`/`Models`/`Store`/`Bridge` impacted or full/release), & ESDD Spec/Headless audit (`ubuntu-latest`).
        - `[Gate 1]` `swift test --package-path apps/ios/Packages/AntigravityData` (when `apps/ios/Packages/AntigravityData` impacted or full/release).
        - `[Gate 2]` `python3 verification/verify-live-rpc-flow.py`, `python3 verification/verify-v233-capabilities.py`, & `python3 verification/verify-compat-matrix.py` (when protocol/bridge impacted or full/release).
        - `[Gate 2.5]` `./gradlew :shared:umbrella:assembleAntigravitySharedDebugXCFramework --no-daemon` (cached on normal PRs; fresh build on release or `shared/` changes).
        - `[Gate 3-5]` `python3 verification/ios-simulator-runner.py --plan verification/output/e2e-plan.json` (`skip`, `build-only`, `scoped`, or `full`/`release` — running only impacted modular `AntigravityUITests` & Simulator screens on scoped PRs, and all 5 XCUITests + Live App RPC + all 13 screens on full/release).
        - `[Release Mandatory]` Full KMP JVM + iOS Simulator XCFramework E2E (automatically enforced when `is_release == true`).
     6. **Automatic Failure Repair Loop**: If **any** CI gate fails (Kotlin/Native, SKIE, Swift 6 compiler/type-check/concurrency error, `XCTest` failure, `xcodebuild` failure, real Simulator `XCUITest` failure, or merge conflict with `origin/main`), inspect the exact failure logs (`gh run view <run-id> -R venciallee/PocketAntigravity --log-failed`), fix the root cause (or merge latest `origin/main`), commit, push to the same PR branch, and re-run until **all gates pass 100% green**.
     7. **Auto Merge into `main`**: Once all CI checks are `SUCCESS` and the PR is `MERGEABLE`, automatically squash-merge the PR into `main` (`gh pr merge <pr-number> -R venciallee/PocketAntigravity --squash --delete-branch`), fast-forward local `main`, and report the merged PR link, `main` commit SHA, and green CI run link to the user.
     8. **Visual Screenshot Inspection (Optional)**: When verifying visual iOS rendering changes, you may also download the `real-ios-simulator-verification` workflow artifact (`gh run download <run-id> -n real-ios-simulator-verification`) to inspect real iOS Simulator screenshots directly.


4. **PR / MR Merge Conflict Auto-Detection & Resolution (Mandatory Before Handoff)**:
   - Whenever you create or update a Pull Request targeting `main`, you **MUST** verify the PR has zero merge conflicts **both immediately after creating/updating the PR AND again right after macOS CI completes** (since other PRs may merge into `main` while CI is running):
     1. Run `git fetch origin` and check `gh pr view <pr-number> -R venciallee/PocketAntigravity --json mergeable,mergeStateStatus` (re-check briefly if `mergeable` is still `"UNKNOWN"` while GitHub computes the merge preview).
     2. If `mergeable == "CONFLICTING"` or `mergeStateStatus == "DIRTY"` (or `origin/main` has new commits conflicting with the PR):
        - Automatically run `git merge origin/main`, resolve all conflicts cleanly (preserving both `origin/main` fixes and this PR's changes), commit, and push to the PR branch.
        - Re-run local fast verification (`esdd-verify.py` / `verify-live-rpc-flow.py` / `verify-compat-matrix.py`) and wait for the updated `macos-15` CI workflow run on the new merge commit to pass 100% green.
        - Re-check `gh pr view <pr-number> --json mergeable,mergeStateStatus` until `mergeable == "MERGEABLE"` and `mergeStateStatus` is `"CLEAN"` (or `"UNSTABLE"`/`"BLOCKED"` only if non-conflict policy applies — never `"DIRTY"`).
     3. Never hand off a PR to the user for merge while `mergeable == "CONFLICTING"` or `mergeStateStatus == "DIRTY"`.

5. **Automated Bidirectional Compatibility Guardrails (Mandatory for Every Feature Iteration)**:
   - Mobile ↔ Desktop compatibility (both newer mobile → older PC and newer PC → older mobile, with zero upstream Desktop changes) is mechanically enforced by `verification/verify_compat_guardrails.py` (impact-scoped Gate 0 & ESDD Stage 1 when `Protocol`/`Models`/`Store`/`Bridge` change, plus mandatory on full/release) and `verification/verify-compat-matrix.py` (Gate 2):
     1. **Register every Connect-RPC method**: Whenever adding a new RPC call under `apps/ios/Packages/AntigravityData/Sources/AntigravityData/Protocol/`, register it in `HostCapabilityRegistry.swift` (`HostCapability.rpcMethods`, `coreBaselineMethods`, or `legacyAliasMethods`). Non-core RPCs automatically receive per-host negative caching on `404/501/unimplemented`.
     2. **Resilient forward-compatible enums**: Every `String`-backed `Codable` enum in `apps/ios/Packages/AntigravityData/Sources/AntigravityData/Models/` MUST conform to `ResilientStringEnum` (or implement a custom fallback `init(from:)`) so future PC enum values never throw `DecodingError`.
     3. **No silent `try?` fake successes on live writes**: Never wrap mutating RPC calls in `Store/*.swift` with silent `try?`; use `performLiveCapabilityWrite(...)` or explicit `do/catch` + `handleLiveCapabilityWriteError(...)` with state rollback on live backends (while preserving offline ESDD mode).
     4. **Keep Swift & Companion Bridge enum downgrades in sync**: Any new entry added to `ProtocolCompatibilityEngine.downgradedEnumReplacement` must also be added to `BRIDGE_ENUM_DOWNGRADES` in `scripts/mac-companion-bridge.py` (unmapped future enums automatically fall back to stripping the holding key).

6. **Advisory Runtime & Cross-Boundary Hygiene (Non-Blocking / Warning-Only)**:
   - Run `python3 verification/verify_advisory_hygiene.py` (automatically invoked in advisory warning-only mode during `./scripts/verify.py` and CI Gate 0; emits `[WARN]` / GitHub `::warning::` annotations without blocking merges):
     1. **KMP/SKIE `@Throws(Throwable::class)` & `CoroutineExceptionHandler`**: Every public `suspend fun` exposed from `shared/` (`AntigravityCoreCoordinator`, `*DomainStore`, `shared/umbrella`) MUST carry `@Throws(Throwable::class)` so non-cancellation Kotlin exceptions bridge cleanly to Swift `catch` instead of aborting iOS (`SIGABRT` via `propagateExceptionFinalResort`). Background `CoroutineScope`s must attach a `CoroutineExceptionHandler` and wrap `scope.launch` in `try/catch` (rethrowing `CancellationException`).
     2. **KMP-First Cloud Relay Parity & Never Swallow `401/403`**: Main-app networking runs on `AntigravityKmpRpcClient.kt`; keep Cloud Relay auth/API-key discovery/cookie isolation (`HTTPShouldSetCookies = false`, `HTTPCookieStorage = null`) in sync across KMP & Swift, and never swallow `Unauthorized` into an empty conversation list or fabricate a raw-UUID `.CONNECTED` host.
     3. **Frame 0 Zero-Blocking Launch Baseline**: Keep `UILaunchScreen.UIColorName: LaunchBackground` and `ENABLE_DEBUG_DYLIB: NO` in `project.yml`, and never put synchronous Keychain XPC (`SecItemCopyMatching` / `*Sync`) or synchronous directory creation inside `AntigravityApp.init`, `prepareFastLaunchSessionState()`, or `LocalProjectionStore.init`.
     4. **ESDD vs Live UI Parity**: Avoid hiding persistent Live-mode UI rows/strips behind unconditional `if !store.isVerificationMode {` blocks in `ChatComposerView` (which makes ESDD visual regression blind to live clutter), and gate deferred features like `/btw` behind a single feature flag rather than hardcoding across models/menus.
